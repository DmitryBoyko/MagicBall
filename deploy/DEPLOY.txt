# Шпаргалка деплоя MagicalBall
# Заливка на VPS — только руками (WinSCP + bash). Авто-ssh/scp не использовать.
#
# Каталог на VPS: /opt/magicalball/
# API снаружи:    http://<VPS_IP>:<API_PORT>   ← default http://147.45.173.26:18437
# Внутри контейнера всегда :8000 — в Godot его НЕ пиши, если API_PORT другой.
# TrueTaro на том же хосте: /opt/truetaro  порт 17878 — не смешивать.
# Полный гайд:    docs/vps-deploy.md

══════════════════════════════════════════════════════════════
## ПОРТЫ
══════════════════════════════════════════════════════════════

  VPS IP       147.45.173.26              ← VPS_IP в .env
  Хост VPS     API_PORT  (default 18437) ← сюда бьёт Godot + firewall
  Контейнер    8000                       ← только docker-сеть
  TrueTaro     17878                      ← чужой стек, не занимать

  Проверка занятости:
    ss -tlnp | grep -E ':18437|:17878|:19448|:8000|:18087|:18088' || true
  Если 18437 занят → в .env: API_PORT=<другой>  и тот же порт в android_base_url

══════════════════════════════════════════════════════════════
## ПЕРВЫЙ ДЕПЛОЙ
══════════════════════════════════════════════════════════════

### На ПК
  cd C:\epm-games\MagicalBall
  .\deploy\prepare-winscp.ps1
  → deploy\winscp-upload\

### WinSCP → /opt/magicalball/
  Залить СОДЕРЖИМОЕ deploy\winscp-upload\ в /opt/magicalball/
  (чтобы появился /opt/magicalball/docker-compose.yml)
  НЕ перезаписывай .env на сервере целиком после первого init.

### На VPS
  mkdir -p /opt/magicalball
  cd /opt/magicalball
  cp deploy/env.example .env
  nano .env          # GIGACHAT_CREDENTIALS=...  VPS_IP=147.45.173.26  API_PORT=18437
  chmod +x deploy/*.sh
  bash deploy/check-env.sh
  # firewall: TCP API_PORT (18437)
  bash deploy/install-on-vps.sh

### Проверка
  curl -s http://127.0.0.1:18437/health
  curl -s http://147.45.173.26:18437/health
  # {"status":"ok","service":"magicalball"}

### Godot
  Редактор:  "proxy_base_url": "http://127.0.0.1:18437"
  APK:       "android_base_url": "http://147.45.173.26:18437"
